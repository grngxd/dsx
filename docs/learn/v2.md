# COMPONENTS V2

dsx supports **Discord Components V2** alongside the traditional Discord message layout.

Components V2 gives you a different set of Discord-native UI primitives for building richer message layouts.

to use Components V2, add the `v2` prop to `Message`:

```tsx id="7qkz8w"
<Message v2>
    ...
</Message>
```

# BASIC V2 MESSAGE

a simple Components V2 message can look like this:

```tsx id="4j6m2r"
<Message v2>
    <TextDisplay>
        # Hello from DSX
    </TextDisplay>
</Message>
```

V2 messages use Discord's component hierarchy instead of the traditional message content/embed structure.

# CONTAINERS

`Container` groups components into a single visual section.

```tsx id="3m8p5c"
<Message v2>
    <Container>
        <TextDisplay>
            # Hello
        </TextDisplay>

        <Separator />

        <TextDisplay>
            built using Components V2!
        </TextDisplay>
    </Container>
</Message>
```

containers can optionally have an accent color:

```tsx id="q6v2kx"
<Container accentColor={0xff00ff}>
    ...
</Container>
```

and can be marked as spoilers:

```tsx id="s9m4hd"
<Container spoiler>
    ...
</Container>
```

# TEXT DISPLAY

`TextDisplay` renders text directly into a V2 message.

```tsx id="z2k7qp"
<TextDisplay>
    # Hello world!
</TextDisplay>
```

it can contain normal JSX expressions:

```tsx id="y4n8cw"
const name = "grng";

<TextDisplay>
    Hello, {name}!
</TextDisplay>
```

`TextDisplay` can be used directly inside a V2 message, a `Container`, or a `Section`.

# SEPARATORS

use `Separator` to visually separate parts of a V2 layout.

```tsx id="f5r2jn"
<Separator />
```

by default, it renders a divider.

you can control the divider and spacing:

```tsx id="k8q3mv"
<Separator
    divider
    spacing={2}
/>
```

`spacing` can be `1` or `2`.

# SECTIONS

`Section` creates a layout containing one or more `TextDisplay` components and a single accessory.

```tsx id="v7m2cx"
<Section>
    <TextDisplay>
        # Profile
        grng
    </TextDisplay>

    <Thumbnail
        url="https://example.com/avatar.png"
        description="profile picture"
    />
</Section>
```

the accessory can be either a `Thumbnail` or a `Button`.

for example:

```tsx id="n6x3qp"
<Section>
    <TextDisplay>
        ## Settings
        Edit your profile.
    </TextDisplay>

    <Button onClick={interaction => {
        ...
    }}>
        Edit
    </Button>
</Section>
```

a section can contain between **1 and 3 `TextDisplay` components** and exactly one accessory.

# THUMBNAILS

`Thumbnail` is used as a section accessory.

```tsx id="c4p8vx"
<Section>
    <TextDisplay>
        ## Profile
        grng
    </TextDisplay>

    <Thumbnail
        url="https://example.com/avatar.png"
        description="profile picture"
    />
</Section>
```

you can mark thumbnails as spoilers:

```tsx id="m7q2rd"
<Thumbnail
    url="https://example.com/image.png"
    spoiler
/>
```

# BUTTON ACCESSORIES

buttons can also be used as the accessory of a section:

```tsx id="f3k9wm"
<Section>
    <TextDisplay>
        ## Settings
        Open the settings menu.
    </TextDisplay>

    <Button onClick={interaction => {
        ...
    }}>
        Settings
    </Button>
</Section>
```

link buttons are supported as section accessories too:

```tsx id="x8p4nv"
<Section>
    <TextDisplay>
        ## DSX
        View the project on GitHub.
    </TextDisplay>

    <Button
        style={ButtonStyle.Link}
        url="https://github.com/grngxd/dsx"
    >
        GitHub
    </Button>
</Section>
```

# MEDIA GALLERIES

`MediaGallery` displays one or more media items.

```tsx id="d5m8qk"
<MediaGallery>
    <Media
        url="https://example.com/cat.png"
        description="a cat"
    />

    <Media
        url="https://example.com/dog.png"
        description="a dog"
    />
</MediaGallery>
```

a gallery must contain at least one `Media` and can contain up to **10** items.

# MEDIA

`Media` represents an individual item inside a `MediaGallery`.

```tsx id="j7q3mx"
<Media
    url="https://example.com/image.png"
    description="example image"
/>
```

media can also be marked as spoilers:

```tsx id="r5n2vc"
<Media
    url="https://example.com/image.png"
    spoiler
/>
```

# FILES

`File` adds a file component to a V2 message.

```tsx id="w8k4pz"
<File url="attachment://example.txt" />
```

files can also be marked as spoilers:

```tsx id="y3m7qx"
<File
    url="attachment://example.txt"
    spoiler
/>
```

# ACTIONS IN V2

`Actions` can be used in a V2 message or inside a `Container`.

```tsx id="p4k8mc"
<Message v2>
    <Actions>
        <Button onClick={interaction => {
            ...
        }}>
            Click me
        </Button>
    </Actions>
</Message>
```

dropdowns can also be placed inside `Actions`:

```tsx id="n7q2vx"
<Actions>
    <Dropdown
        type="string"
        options={[
            {
                label: "Red",
                value: "red",
            },
            {
                label: "Blue",
                value: "blue",
            },
        ]}
    />
</Actions>
```

an `Actions` component can contain buttons or a dropdown, but should not mix both.

# V2 HIERARCHY

DSX validates the V2 component hierarchy before rendering.

the supported structure is roughly:

```text id="h6r4qp"
Message
├── TextDisplay
├── Separator
├── MediaGallery
├── File
├── Section
├── Container
└── Actions

Container
├── TextDisplay
├── Separator
├── Section
├── MediaGallery
├── File
└── Actions

Section
├── TextDisplay
├── TextDisplay
├── TextDisplay
└── Button / Thumbnail

MediaGallery
└── Media

Actions
└── Button / Dropdown
```

the exact nesting rules are enforced by dsx's V2 validation.

# V2 AND REACTIVITY

Components V2 work with the same reactive state system as normal DSX messages.

```tsx id="t9m3vx"
const Counter = component(() => {
    const count = useSignal(0);

    return (
        <Message v2>
            <Container>
                <TextDisplay>
                    count: {count.value}
                </TextDisplay>

                <Actions>
                    <Button
                        onClick={() => count.value++}
                    >
                        +
                    </Button>
                </Actions>
            </Container>
        </Message>
    );
});
```

when `count.value` changes, DSX rerenders the V2 message in the same way it would a normal message.

# V2 AND RESUMABILITY

V2 interactive components can also be resumable.

```tsx id="b6q2zn"
const App = component(() => {
    const count = useSignal(0);

    return (
        <Message v2>
            <Container>
                <TextDisplay>
                    count: {count.value}
                </TextDisplay>

                <Actions>
                    <Button
                        onClick={() => count.value++}
                    >
                        +
                    </Button>
                </Actions>
            </Container>
        </Message>
    );
});
```

because the component is registered with `component()`, its interactive state can continue working after a bot restart.

# BUILDING A COMPLETE V2 MESSAGE

putting several V2 components together:

```tsx id="q8m4kc"
const App = component(() => {
    const count = useSignal(0);

    return (
        <Message v2>
            <Container accentColor={0xff7ab8}>
                <TextDisplay>
                    # DSX Counter
                </TextDisplay>

                <Separator />

                <Section>
                    <TextDisplay>
                        current count: {count.value}
                    </TextDisplay>

                    <Button
                        onClick={() => count.value++}
                    >
                        +
                    </Button>
                </Section>

                <Separator />

                <Actions>
                    <Button
                        onClick={() => count.value = 0}
                    >
                        Reset
                    </Button>
                </Actions>
            </Container>
        </Message>
    );
});
```

this combines **Components V2**, **reactive state**, and **resumable interactions** in one component.
